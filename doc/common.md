# mdview 共通仕様

GUI版（`gui/`）とTUI版（`tui/`）の両方が守る決まりをまとめる。

- 各版の要求仕様（`gui/doc/requirement.md`、`tui/doc/requirement.md`）は、この文書を前提にして、その版に固有の内容だけを書く。
- 共通の決まりを変えるときは、先にこの文書を直してから、両版の要求仕様・実装・テストに反映する。
- 現状どちらかの版が決まりに合っていない点は、7章にまとめる。
- 両版はコードを共有しない。「同じ挙動」は、同じ規則をそれぞれの言語で実装することで実現する。

## 1. 対象ファイル

- 拡張子が `.md` または `.markdown` のファイルを Markdown ファイルとして扱う。拡張子の大文字・小文字は区別しない。
- 文字コードは UTF-8 とする。先頭の BOM は読み飛ばす。
- UTF-8 として正しくないファイル（Shift_JIS など）は、文字化けしたまま表示せずにエラーとして扱い、理由を知らせる（GUI版はエラーバナー、TUI版は起動時なら標準エラー出力に出して終了、起動後ならステータスバー）。
- 改行は LF・CRLF のどちらでも同じように表示する。

## 2. Markdown の対応範囲

- CommonMark の基本構文（見出し、段落、強調、リスト、引用、コード、リンク、水平線など）に対応する。
- GFM の拡張のうち、次の4つに対応する。
  - 表
  - タスクリスト
  - 取り消し線
  - 自動リンク（`https://...` などの URL をそのままリンクにする）
- コードブロックは、言語の指定に応じてシンタックスハイライトする。
- 生の HTML は描画せず、書かれた文字列をそのままテキストとして表示する。

画像、Mermaid 図、数式をどう表示するかは版ごとに決める（6章）。

### 2.1 フロントマター

ファイル先頭の YAML 形式のフロントマターは、本文と分けて解釈し、文書の情報として本文の先頭に表示する。

- 1行目が `---` だけの行（末尾の空白は可）で、その後に `---` または `...` だけの行が現れるまでの部分をフロントマターとする。閉じの行が無い場合はフロントマターとして扱わず、これまで通り水平線として表示する。ファイルの途中にある `---` も水平線のまま。
- YAML 形式のみに対応する（TOML 形式の `+++` などは対象外）。
- フロントマター部分は本文として扱わない。水平線や見出しとして表示されたり、目次に現れたりしない。
- 値は書かれた通りの文字列として扱う。`date: 2026-10-08` の日付の書式や、`version: 1.10` の数値（`1.1` にしない）は変換しない。
- 表示する内容
  - `title` を題名として目立たせて表示する。`author` と `date` は、その下に ` ・ ` でつないだ1行にまとめる。`author` が配列なら「、」でつなぐ。
  - それ以外の項目は、キーと値の一覧として書かれた順に表示する。値が配列なら `, ` でつなぎ、入れ子のオブジェクトは `キー: 値` を `, ` で並べた1行にする。
  - 書かれていない項目は表示しない。表示する項目が1つも無い場合（空のフロントマターを含む）は何も表示しない。
  - 本文に `title` と同じ文言の見出しがあっても、両方そのまま表示する。目次には `title` を出さない。
  - 表示は本文の一部として扱い、検索の対象に含める。
- YAML として解釈できない場合（構文の誤り、最上位がキーと値の形式でない場合）は、`フロントマターを解釈できませんでした: <理由>` と元の文字列を本文の先頭に表示し、本文はフロントマター部分を除いて通常通り表示する。

文字の大きさ・色・区切り線などの見た目は版ごとに決める。

- GUI版：`gui/doc/requirement.md` 3.12
- TUI版：`tui/doc/requirement.md`「フロントマター」

## 3. 見出しと目次

### 3.1 目次

- 見出し（`#`〜`######`）を、文書に現れた順に目次に並べる。
- 目次の項目を選ぶと、本文の該当する見出しへ移動する。

### 3.2 見出しのアンカー（slug）

見出しには、リンクの `#アンカー` で指定するための識別子（slug）を付ける。規則は GitHub と同じにする。

1. 見出しのテキスト（強調・コードなどの装飾を除いた文字列）を小文字にする。
2. 文字（各国語の文字を含む）・数字・`_`・`-`・半角スペース以外の文字を取り除く。全角スペースも取り除かれる。
3. 半角スペースを `-` に置き換える。連続したスペースはまとめずに、それぞれ `-` にする。
4. 同じ文書の中で同じ slug がすでにあれば、末尾に `-1`、`-2`、… を付けて区別する。

| 見出し | slug |
|---|---|
| `Hello World` | `hello-world` |
| `3.1 ファイルを開く` | `31-ファイルを開く` |
| `API (v2) — 概要` | `api-v2--概要` |
| `C++ / C#` | `c--c` |
| `日本語　全角スペース` | `日本語全角スペース` |
| `Foo` を3回 | `foo`、`foo-1`、`foo-2` |
| `Foo`、`Foo`、`Foo-1` の順 | `foo`、`foo-1`、`foo-1-1` |

各版の実装は次のとおり。

- GUI版：rehype-slug（内部で github-slugger 2.0.0 を使う）
- TUI版：`tui/src/mdview_tui/slug.py`

2026-11-21 に上の表の例を含む15個の見出しを両方の実装に通し、すべて同じ slug になることを確かめた。例外は前後に空白を持つ文字列だけで、TUI版は空白を取り除いてから変換する。ただし Markdown の見出しは解析の時点で前後の空白が除かれるため、実際の表示に差は出ない。

## 4. リンク

本文中のリンクは、リンク先によって次のように扱う。

| リンク先 | 例 | 動作 |
|---|---|---|
| 同じ文書の中のアンカー | `#概要` | 同じ文書の、slug が一致する見出しへ移動する |
| スキームを持つ URL（`file:` を除く） | `https://...`、`mailto:...` | OS の既定のアプリ（ブラウザなど）で開く。ビューアの中では開かない |
| `file:` の URL | `file:///C:/docs/x.md#概要`、`file://server/share/x.md` | ローカルファイルへの絶対パスとして扱い、下の2行と同じ規則に従う。OS には渡さない（`file:///C:/Windows/System32/calc.exe` のようなリンクでプログラムが起動するのを防ぐため） |
| Markdown ファイルへのパス | `other.md`、`../doc/spec.md` | ビューアの中で開く |
| Markdown ファイルへのパスとアンカー | `other.md#概要` | ビューアの中で開き、該当する見出しへ移動する |
| それ以外のローカルファイル | `image.png`、`data.csv` | 開かない |

- 相対パスは、表示中のファイルがあるディレクトリを起点に解決する。
- パスとアンカーに含まれる `%20` などのパーセントエンコードは、元の文字に戻してから扱う。
- 1文字だけのスキーム（`C:` など）は、URL ではなく Windows のドライブ名として扱う。
- 開けないリンクを選んだときは、表示中の内容を変えずに、理由を利用者に知らせる（GUI版はエラーバナー、TUI版はステータスバー）。文言は両版で揃える。
  - Markdown 以外のローカルファイル: `サポートしていないリンク: <リンク先>`
  - 存在しない、または読めないファイル: `ファイルが見つかりません: <パス>`（TUI版は読み込みのエラーメッセージをそのまま出す）
  - 一致する見出しが無いアンカー: `見出しが見つかりません: #<アンカー>`
  - 外部 URL を開けなかった: `ブラウザを開けませんでした`（GUI版は後ろに URL を付ける）

## 5. 閲覧専用と自動再読込

- ビューアは、表示中の Markdown ファイルに書き込まない。編集は外部エディタに任せ、ビューアにはそのファイルを外部エディタで開く操作を用意する。
- 表示中のファイルが更新されたら、自動で読み込み直して表示を更新する。
- 本文の中を文字列で検索できる。大文字と小文字は区別しない。一致した箇所はすべてハイライトし、次・前の一致へ移動できる。

## 6. 版ごとに異なってよいもの

次の項目は、使われる環境に合わせて版ごとに決める。詳細は各版の要求仕様を参照。

| 項目 | GUI版 | TUI版 |
|---|---|---|
| 対象環境 | Windows | Linux / WSL / macOS |
| 同時に開くファイル | 複数（タブ） | 1つ（リンクで移動し、戻る／進むで行き来する） |
| 標準入力からの表示 | なし | あり |
| 画像 | 描画する | 描画せず、代替テキストとリンク先を表示する |
| Mermaid 図・数式（KaTeX） | 描画する | 描画しない |
| テーマ | OS の設定に追従する | ダーク／ライトを手動で切り替える |
| 外部エディタ | 設定したコマンド（既定は `emacs`） | `$VISUAL` → `$EDITOR` → `vi`（Windows では `notepad`） |
| キー操作 | `Ctrl+F`・`Ctrl+E`・`Ctrl+W` などのデスクトップ風 | less / vim 風 |
| Word 形式で保存、表示の拡大・縮小 | あり | なし |

これまでに解消した差異は次のとおり。詳しい経緯は git の履歴を参照。
